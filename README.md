# 序作工作台 2.6.3

## macOS 版本

`develop-macos` 分支提供 macOS 13 及以上版本适配，包括原生窗口按钮、Command 快捷键、文件与磁盘浏览、Office 导出、跨平台备份恢复和独立动画运行时。源码启动、DMG 打包及测试命令见 [macOS 开发与验收](MACOS.md)。

Apple Silicon 安装包位于本地 `outputs/release-v2.6.3/`，使用 DMG 拖入 Applications 安装。macOS 更新采用新版 DMG 替换，卸载通过 Finder；Windows 安装与维护流程保留。当前本机验收针对 Apple Silicon；Intel 由独立 CI 构建与回归，未经运行的结果不计入本机验收。

外部模型调用需要自己的供应商配置与 Key，离线回归不代表所有供应商均已联网验收。外部 Office 转 PDF 需要安装 LibreOffice；本机未安装，因此该外部程序的实际转换不计入已完成验证。

## 当前版本

- 首页聊天区按实际内容高度排列，输入卡不会覆盖“最近作品”；页面正常纵向滚动，长聊天记录保留独立滚动。

- 聊天输入区采用分组布局：制作格式与使用场景并排，长模型名保持单行，窄窗口自动分行；浅深主题均保留清晰间距与键盘焦点。

- 聊天输入区支持添加图片、PDF、文字和 Office 附件，并可选择内置或自定义使用场景。原始附件随消息、重试和工作区备份保留，制作前会加入目标项目。

- 首页同一输入区切换“聊天 / 制作”。普通聊天支持连续沟通、流式回复、停止、重新回答与会话恢复，不要求创建项目；制作先生成完整方案，点击制作时再选择保存项目。
- 对话模型旁可选择推理强度，默认自动。根据供应商、协议与具体型号提供可用等级；单个 Key 显示账户摘要，多账户可切换。已发生的聊天与制作费用分别记账并计入工作区总额。
- 模型提供一次快速接入向导；制作结果支持文件名、缩略图选择与就地异常处理。完整工作区备份包含普通聊天及费用，按项目备份保留项目范围。
- 图片工作台的“更多设置”和“格式”支持直接输入 1–20 张并保留设置；也可按独立描述与张数分组生成。多张逐张执行，精修每张使用同一份原始参考图。
- Word、PPT 和 Excel 支持应用内编辑、素材插入及 Office 文件导出；提供历史版本、撤销与重做。工作区与项目分别管理本地文件夹。
- 失败后继续不重复已成功的图片，取消保留已有结果。每次调用费用独立累计，撤销、删除或取消不会抹去已发生费用。
- 完善资源分类、回收站、任务整理、工作台折叠记忆及操作流程。

普通聊天采用独立持久化、请求编号幂等、取消后保留用量及费用；流式仅发送当前回复增量状态，输入草稿延迟保存。原生验收使用隔离配置与本地可控服务，真实账户验证另行记录，不能据此推定所有外网供应商均已联网验收。

正式安装包与 OTA 资源见 [GitHub Releases](https://github.com/xiandan001/xuzuo-studio/releases)。以下按版本记录之前的功能与验证边界。

## 自定义安装与界面一致性（0.13.0）

- 安装、更新、目录浏览、进度、错误重试和卸载改用轻量自绘WPF窗口与ZIP/SHA事务引擎，不再调用默认NSIS向导。默认当前用户安装、不请求管理员权限；系统UAC/SmartScreen仍属于Windows自身界面。
- 安装使用同卷暂存、逐文件校验和可恢复切换；卸载仅处理受管文件，保留未知/改动内容、工作区、费用和密钥资料。已安装应用的“偏好设置 → 数据与版本”可打开自定义卸载窗口。
- 修复新项目表单焦点边框越出滚动区，统一内绘焦点与620px窗口边界；标题栏、侧栏使用同一正式图标，去掉旧紫色底层。
- 工作区面包屑可返回总览并保留未保存编辑保护。真实成品卡片区分已生成和已确认交付；确认交付经后台复核绑定当前工作流，不再被重复轮询降级；修改、撤销检查或新任务会使完成绑定失效。

## 性能与工作区管理（0.12.0）

- 文件窗口先显示可浏览目录，再后台识别磁盘；项目范围窗口不做整机磁盘查询。运行时改用5.6KB只读磁盘助手，取消PowerShell启动，增加15秒缓存、失败冷却、强制刷新和关闭取消。
- 页面按需加载；移除全屏模糊，暂停失焦或隐藏窗口的CSS动效，辅助功能交给系统检测。业务任务和保存继续执行。
- 备份配置改为点击时读取最新数据；文档恢复写复用缓存串，手动重试/退出/导出仍读取最新输入；表格辅助面板序列化按工作簿变化缓存。
- 工作区支持移除和恢复。移除只隐藏列表项，保留本地文件、项目、费用、提示词和目录登记；当前工作区移除后切换到其它可见工作区，至少保留一个。运行、暂停、待审核任务或未保存编辑会阻止移除。

## 项目文件夹第二步指引（0.11.3）

- 修复新工作区显示0项、点击却提示非空的误导。项目窗口明确显示“第2步”和可见子文件夹数量；工作区根目录的主按钮引导新建项目子文件夹。
- 项目命名后“创建并继续”直接使用新返回的真实目录，不再多点一次确认；已有空子目录仍可直接选择。重名时保留输入，取消不会提交工作区根目录。
- 后端先识别工作区根目录，再验证实际空目录。普通文件、隐藏文件和控制标记仍会阻止占用或覆盖，不把列表中的0个子文件夹当作磁盘空目录。

## 新位置工作区创建与对话框边界（0.11.2）

- 工作区失联时明确区分“恢复原工作区”和“在新位置新建工作区”。新位置使用独立编号，不把原工作区改绑到空目录；旧项目、费用和回收站记录保留。
- 新建工作区后继续选择项目子文件夹，保留已填写的类型、名称、需求、预算和提示词。取消第一步不登记工作区，取消第二步保留已建工作区并允许继续。
- 原路径恢复窗口明确提示用途；只有在原父目录才能补建原文件夹，名称固定。其它位置提供返回选项，不再把通用新建按钮放在无法完成的位置。
- 统一对话框页面根层、内容和备用退出界面的圆角与裁切，显式启用原生圆角及可缩放厚边框；保持不透明窗口和原有退出协议。

## 本地与可移动磁盘识别修复（0.11.1）

- 修复磁盘枚举超时后只显示当前盘的问题：使用 .NET DriveInfo 读取本地盘和可移动盘元信息，避免慢速 CIM 查询，区分本地磁盘和可移动磁盘。
- 文件窗口的刷新按钮同时更新目录和磁盘列表；窗口重新激活时也会刷新，去掉原来的30秒缓存。同一时间的磁盘请求合并，目录和文件名保持不变。
- 识别失败会保留已知位置并提供明确提示及重试入口；刷新继续执行原有工作区范围、受保护路径及原位置确认规则。

## 统一自定义对话框（0.11.0）

- 文件夹、文件导入、另存和应用确认窗口均使用应用自己的界面，明暗主题与配色同步。文件窗口采用资源管理器布局：常用位置/磁盘、返回/上级/面包屑、路径输入、当前目录搜索、分页、新建文件夹和固定操作区。
- 新建文件夹在窗口内输入，同名或非法名称就地提示；项目仍限制在当前工作区的空独立目录，原位置重连保持原身份规则。列表仅浏览元信息，禁止链接、应用私有目录与控制文件。
- 另存同名文件需要自定义覆盖确认，并在最终写入时再核对目标；取消不报告保存成功。桌面JSON/CSV/恢复稿也走相同另存流程。
- 应用内18类模态统一层级、焦点、键盘、背景禁用、正文滚动、标题/字号/按钮；抽屉与非模态菜单保持各自语义，默认不逐次确认生成费用。
- 自定义文件窗口与退出确认使用独立沙箱renderer。文件系统准备时先显示加载窗口，取消无需等磁盘枚举；主界面卡住时退出确认仍可用。退出先取消待选文件再等待写入，保留明确强退和重载入口。
- 浏览器预览没有真实文件系统桥时会明确提示桌面版；OS权限/UAC与外部Office软件窗口不属于应用自身界面。

## 新建项目的工作区连接恢复（0.10.3）

- 新建、更换或提交项目时遇到工作区连接异常，显示带原路径和实际操作按钮的持久恢复面板；重新连接后继续原操作并保留填写信息与模板。
- 显式重新选择原登记的工作区目录后，可补真正缺失的连接标记。允许已删除旧目录保持缺失，不重建文件，不改变账本和回收站。仍存在的项目必须核验身份，损坏/冲突标记、错误位置和链接不覆盖。
- 原有严格身份修复规则保留；取消恢复或取消后续目录选择均可继续，不再只给一个当前页面不存在按钮的提示。

## 先选项目文件夹（0.10.2）

- 新建项目先选择或在系统窗口中新建当前工作区内的空项目文件夹，随后填写项目名称、类型及需求；默认名称来自文件夹，顶部显示完整路径并可更换。
- 普通入口与无匹配项目的提示词模板入口统一执行这个顺序。取消选择不新建项目；关闭表单保留用户在系统中新建的空文件夹。
- 选择时只检查，提交时重新检查身份和空目录。根目录、外部位置、应用保留目录、其他项目、非空目录和链接均不会被当新项目覆盖；提交重试保持同一ID。
- 首次未设置工作区位置时先明确绑定工作区，再选择项目目录。浏览器预览会明确提示本地创建需要桌面版；批量生产继续在已选工作区内自动建立各项独立子目录。

## 自动费用恢复（0.10.1）

- 对本应用发出的官方 Responses 请求保存缓存请求形状。供应商仅返回缓存写入总量时，依据可证明的默认30分钟时长补齐计费拆分；保留原始用量与旧金额修订。代理、不明请求和矛盾拆分不套默认。
- 启动自动复算历史，后台每分钟按需重试，窗口恢复触发受节流检查；不重新生成、不调用模型、不要求用户计算或填写金额。退出时取消汇率请求并等待本地落盘。
- 精确原币与参考人民币继续保留；缺少依据时直接说明具体原因，静态缺项不再显示为似乎一直在计算。

## 编辑、交付与生产闭环（0.10.0）

- 文档精修支持 Word 当前段落/表格/单元格、PPT 当前页面与全文文字、Excel 区域。先生成建议，再查看前后差异并应用；过期建议不覆盖新内容，应用可撤销，调用费用照常累计。
- Word 表格可逐格编辑、增删行列、设置表头/边框；DOCX 为真实可编辑表格。
- 文档及图片的验收绑定实际文件、哈希和编辑版本；确认交付后保留历史。客户 ZIP 只含所选成品和说明，内部提示词、密钥、费用和原始参考不进入客户包。
- “偏好设置 → 本地数据”提供完整内部备份、检查导入、重新连接和复制搬迁。备份包含编辑源、独立历史、素材、产物、费用及非密钥配置；导入创建独立工作区，恢复凭据支持重试，不重复累计费用。API Key 始终不随备份移动。
- “我的工作流 → 批量生产”和任务中心支持 CSV/XLSX 每行变量生成独立项目；串行执行、暂停后续、取消及单项明确重试，重启不自动重发不确定请求。
- 连续输入合并撤销、缓存恢复快照、Word 稳定组件、表格格式修改复用计算结果、同文件并发预览合并；历史逐任务保存、列表摘要与按需详情、任务分页。Office 打包及图像 Alpha 扫描使用后台线程，退出保护继续有效。

## 卡顿与退出兜底（0.9.1）

- 退出改为主进程异步协调：界面与后台检查均有限时，保留写入完成后退出；8秒等待仍未完成时提供继续等待或强制退出，正常应用不会自动强退。
- 界面无响应或渲染进程退出时提供重新载入、安全退出和明确的强退选择；不再用同步消息框阻塞主线程。进度层暂停新生成/保存请求，取消检查后可继续工作。
- 原始工作区和费用记录不因退出而删除。强退可能丢失尚未落盘的编辑/用量，需要用户明确选择；诊断日志只记录退出阶段与选择，不记录Key或文稿。
- 独立测试由专用标记识别、窗口明确区分且默认隐藏；测试父进程结束或达到最长生命周期后自动清理，测试程序finally也有进程树清理兜底。正式应用不受该测试生命周期限制。

## 本地生产基线（0.9.0）

- 素材库保存真实文件到工作区 `.xuzuo-assets`，收藏、归档和项目附件在重启后保留。加入项目复制实际文件；文字和 Office 正文进入生成请求，图片可显式选择用于精修。源素材归档不破坏项目副本。
- Word/PPT/Excel支持当前编辑会话的结构撤销/重做、Ctrl+S，文本框保留原生撤销。恢复稿保存失败有重试、下载和离开保护，正常可靠草稿不增加每次切页确认。
- 编辑修订独立保存，主稿损坏或缺失时可预览有效历史，再显式保留坏原稿并恢复为新版本。历史容量不再累加到单一4/16MB主文件；撤销栈不是持久历史，修订也不是全目录灾难恢复备份。
- Excel同Word/PPT一样按精确编辑版本识别真实导出文件，重开可识别，回收或缺失后失效。已登记但后续提交失败的成品可刷新找回，未关联版本不会冒充已验收成品。
- 截断、拒绝、待续、工具调用和缺失结束状态不作为完整文字成品，已返回片段和用量保留，不自动再次调用模型。新产物读取有内容校验，外部同长度改写也不会冒充原始内容。
- 退出冻结新写入，等待模型中断、编辑/产物/素材/密钥写入完成；正常关窗按后台实时状态判断任务，保存失败不冒称成功。
- 报价按工作区与项目独立保存，旧工作区报价作为未分配旧稿保留。月度预算按北京时间月份统计，历史累计单列，无法归月的旧记录明确显示；跨月在分钟/focus/visibility时检查。封面不再展示虚构收入/完成率，最近项目按可信时间排序。
- 新安装从空工作区开始，已有索引和旧版数据保留。搜索支持方向键、Enter、Esc和焦点返回，模态编辑时不在背后打开搜索。默认直接生成、鸢尾紫、明暗模式及两套布局保留。

支持范围是本应用结构化生成和内置编辑的基础Office文稿、受支持公式与图片工作流；复杂动画/宏/特殊图表及任意外部Office原版无损编辑不作为已实现能力。Word 原生表格和范围内文字精修已接入；精修不重建复杂外部原稿版式。事实、视觉版式、公式业务逻辑和素材使用范围仍需人工验收；不承诺自动商业授权或盈利。

具体范围、实现和验收见 `docs/superpowers/specs/2026-11-01-production-baseline.md` 与 `docs/superpowers/plans/2026-11-01-production-baseline.md`。

## 项目菜单遮挡修复（0.8.5）

- 项目更多菜单改用独立浮层，不再被下排卡片或悬停动画遮挡。靠近窗口底部自动向上展开，保持末项可见且可点击。
- 支持方向键、Home/End、Esc 返回触发按钮；点击空白、滚动或调整窗口时关闭，选择操作后直接进入原有编辑、工作台或回收确认流程。

## 正式文档与工作区连接修复（0.8.4）

- 默认 Word / PPT / Excel 快捷创作先生成 `.docx` / `.pptx` / `.xlsx`，再进入人工检查。文本模型的 `result.txt` 作为编辑与恢复源稿保留；本地格式转换不增加模型调用。仅精确匹配旧默认尾部的快捷流程调整顺序，自定义流程不重排。
- 项目文件树将正式 Office 文档置首，明确区分生成源稿、检查报告和其他文字。编辑后的格式导出入口改为“保存为 Word / PPT / Excel”。
- 缺失工作区根标记时显示“检查并恢复工作区”。只有原目录与全部登记项目身份核验通过才独占恢复缺失标记，不覆盖损坏或冲突标记，不创建空项目目录，不恢复在系统中已删除的文件。
- 待检查项目允许移入项目回收站，不再因人工检查阻塞卡片清理，原文件夹不存在也能回收；任务及历史费用保留，恢复项目不会自动执行任务或恢复已丢失的实体文件。真实运行和暂停任务仍需先处理。


## 全面体验审查与可靠性修复（0.8.3）

- 任务空态只新建/打开项目或查看工作流，不再用“演示”标签触发真实调用。

- 每类生成具备内置专业基础要求，再叠加用户本次需求。Word展开正文与执行/验收细节，PPT兼顾每页结论、正文及讲解，Excel设计字段、明细、汇总和说明，图片有按用途的构图/参考一致性要求。内部整理、撰写和自检是单次调用指令，不冒称执行多个模型Agent。
- 快捷完整文档生成默认最大输出12288 Token，用户短篇/指定页数优先；付费确认保留，按实际返回用量计费。明确缺失的关键资料会保持待完善，不因文件成功生成就自动成为可交付。旧稿不会在升级时自动付费重写。

- 配置国内外多家服务连接、真实模型 ID、多把具名 API Key、模型能力、单价和货币；服务地址与地域、站点、服务计划按官方控制台信息填写。

## 真实调用适配范围

下表说明已实现的请求结构。具体模型是否可用、是否接受参数和文件，以及账户、地域、额度、服务计划是否满足要求，仍需由用户对照官方信息验证。勾选能力不是自动适配所有接口。

| 能力 | 已实现协议 | 当前边界 |
| --- | --- | --- |
| 文字生成 | OpenAI Chat 兼容、OpenAI Responses、Anthropic Messages、Gemini 原生 `generateContent` | 模型 ID 由用户填写；不自动替换模型，不自动重新发送失败的付费请求。 |
| 图像理解 | 上述文字协议的图片输入；适合的接口可提交 PDF 或文件 | 必须选有相应能力的模型。普通文字步骤不发送图片；图像理解不将视频当图片发送。 |
| 图片生成、图片编辑 | OpenAI Images 线格式，可在 Images 或相应 OpenAI 连接下使用 | 编辑以实际参考图片提交 multipart；生成保存供应商返回的图片字节。其他厂商是否实现该格式需单独确认，不能由 Chat 兼容直接推断。 |
| 语音合成、语音识别 | OpenAI Audio 的 `speech`、`transcriptions` 线格式 | 合成保存真实音频，识别读取本机音频并保存文字。厂商自有语音协议不会自动转成此格式。 |
| 视频生成 | `providerId=siliconflow` 且协议为 `video` 的硅基流动接口 | 单次提交 `/video/submit` 后查询 `/video/status`，下载实际 MP4；支持的尺寸为 `1280x720`、`720x1280`、`960x960`，图生视频需要参考图。 |
| 视频理解 | Gemini 原生 `generateContent` 的本地 MP4 `inlineData` | 完整内联请求须小于 20 MB，输出保存为 TXT；较大视频需要先压缩或裁剪，当前不会自动上传到 Files API。 |
| 其他专用协议 | 可保存配置，但未适配的能力会被预检阻止 | 不回退为假调用或模拟成功。未知供应商的视频协议仍不支持。 |

OpenAI 已在 **2026-09-24 关闭 Videos API 和 Sora 2 视频模型**，本版本不将其列为可执行视频生成接口。[官方停用公告](https://developers.openai.com/api/docs/deprecations)

视频生成的官方结构依据：[硅基流动提交接口](https://docs.siliconflow.cn/docs/api/video-submit-post)、[状态接口](https://docs.siliconflow.cn/docs/api/video-status-post)。视频理解依据：[Gemini 视频理解](https://ai.google.dev/gemini-api/docs/video-understanding)、[原生 generateContent](https://ai.google.dev/api/generate-content)。服务商后续变更、模型上下线或账户限制可能需要更新适配器。

## API Key 与连接

- 用户自行在 Windows EXE 中填写自己的 Key，不需要把 Key 发到聊天、文档或工单中。应用不替用户创建新 Key。
- 真实密钥仅由 Electron 主进程经系统加密保存到应用数据目录。界面读取名称、末四位、启停状态和更新时间，不提供回读完整已存 Key 的接口。
- 保存、取消或关闭密钥输入框会清空本次输入。系统加密不可用时拒绝保存，不降级为明文文件。
- 网页 `localStorage`、项目、工作流、报价、日志和配置导出不存放明文 Key；配置导出使用白名单，不包含凭证，地址中的查询参数与认证信息也会省略。
- 浏览器预览禁用真实 Key 输入和真实执行；模型中心与凭证由本机各工作区按需引用，不进行云端同步。
- 保存配置或 Key 本身不调用模型。只有用户主动确认认证检查或真实任务后，主进程才通过所选连接使用凭证；认证检查不保证全部模型、余额或多模态接口都可用。
- Base URL、API Key、模型 ID、能力和价目以自己账户的官方控制台为准，不根据厂商名称猜型号、权限、价格或汇率。不同地域、站点和订阅服务的凭证可能不互通。

## 首次使用真实流程

1. **打开新版 EXE，建立项目。** 选择文档或图片，新建时金额上限可直接留空；工作区用于分开管理不同客户或项目。
2. **一次配置模型与 Key。** 在模型中心打开官方目录，按供应商和用途选择型号，再选择或创建对应官方连接，检查带入的 ID、能力与价目后保存。最后由自己在密钥页保存 Key；特殊接口也可返回手动填写。以后可在生成确认中直接选用。
3. **在工作台描述需求。** 图片可导入参考图、选择匹配的模型，尺寸、张数和背景在高级设置中。文档填写内容、样式与需要的参考资料。自己的描述也可保存为提示词模板。
4. **点击生成，在同页确认。** 检查当前项目、模型、Key 与参考文件，自动预检通过后确认费用并开始。多把 Key 时明确选择本次使用的凭证；预检失败会显示修复入口，不自动改用别的服务。
5. **检查真实结果并继续。** 图片直接显示在主区域；文档可查看实际产物或载入草稿修改。在同页任务状态卡完成人工检查，再继续生成实际交付文件。
6. **精修或另存。** 图片选择“精修这张”，描述修改要求，确认新的调用费用。文字草稿可继续编辑后导出实际 Office 文件。用 Office/WPS 或播放器检查成品。
7. **需要复杂流程时再进入高级编辑。** 可以安排多步骤、模板变量、不同模型与人工检查，并将已保存流程绑定为工作台的自定义功能；普通生成不要求先学会编排。
8. **查看总花费与恢复记录。** 成本与报价页保留每次调用、精修与重试费用。未知金额核对账单后再报价；失败后先查看已有结果，避免重复生成已完成的内容。

## 执行、恢复与费用

- 项目预算、工作流单步预算及月度预算均为选填，新建时默认留空。留空表示不设金额上限，应用继续累计每次调用费用并显示总花费；明确填写 `0` 表示零上限。已有预算不会因升级自动清空，可在对应编辑界面删除数值。
- 因步骤预算拦截而停止时，可在“从当前位置继续”的确认窗调整或清空当前步骤的上限；已完成步骤、正文与历史费用保留，不必从头重新生成。此操作不修改原提示词或其他步骤参数。
- 真实运行前预检项目类型、步骤、提示词变量、模型能力、已适配协议、连接、凭证、附件与预算，并由用户确认付费。预检不是供应商的最终费用报价。
- 每次模型执行独立记录，精修、重生成及用户明确选择的重试继续累计；取消或切换旧版本不会抹去已发生费用。
- 暂停通常在当前步骤返回后生效。取消、超时或关闭本地查询，不保证供应商已经停止处理或免除费用；请求已发送而用量不明时记录为待核对。
- 普通步骤失败或中断后再次执行可能重新请求并收费，不能把“继续”一概理解为免费恢复。系统不自动轮换付费备用 Key、不自动重复提交失败的生成请求。
- 硅基流动视频保留提交后的任务 ID。恢复该任务时使用原 ID 查询和下载，不重新调用提交接口；明确选择单步重试时才创建新视频任务。查询结果的费用凭据归回原任务，避免把恢复查询再记为一次生成。
- 视频任务本地等待最多十分钟。视频实际文件时长可从 MP4 容器读取；不能取得时长时保留未知，供应商的推理耗时不当作视频计费秒数。
- 财务页默认查看真实费用，旧记录缺少费用类型时归入模拟。真实、模拟可分别查看，“全部记录”也不把两类金额混成真实报价。
- 用量与用户填写的单价只用于核算，不等于官方自动对账。缓存分档、思考用量、汇率、退款或额外费用可能影响差额；未知费用不显示成免费，存在待核对真实费用的项目不能生成确定的真实报价。
- 当前人民币账本以分为单位，每次计算结果向上取整后累计，适合保守记录成本；可能高于供应商以更细精度汇总的实际扣费。账单核对以供应商原币金额为准。
- 用户可对照官方账单填写本次人民币费用，后台保留原金额与核对记录。报价继续包含人工、后续调用、返工预留和渠道费用，但不保证成交、销量或盈利。

## Office 与画面质量边界

- 可生成实际的、可编辑的 PPTX、DOCX、XLSX 文件。项目 JSON、账本 CSV、报价 JSON 及示意 SVG 仍是各自的数据或预览文件，不冒充 Office 成品。
- GPT Image 2.6 Sunburst／Flare 可用 PNG、JPEG、WebP 静态参考图生成 GIF，账户需具备 GIF 预览权限；SVG 输出仍仅用于文字生成。接口依据见 [OpenAI GIF 指南](https://developers.openai.com/api/docs/guides/image-generation#generate-animated-gif-output)。
- 图片工作台的 GIF 操作按来源区分：静态图片可作为动画参考；本应用有完整生成记录的 GIF 可准备全尺寸静态参考，结合原描述和新的修改要求生成新版本，原动图及费用记录保留；外部 GIF 直接编辑暂不支持，不会静默转成静态图。继续修改不承诺逐帧或无损保留。ChatGPT 网页下载的 GIF 不会带入原会话，在本应用中属于外部文件。
- 生成可编辑文件不等于完整 Office 编辑器。当前不承诺复杂原稿导入后无损保留动画、特殊图表、母版、嵌入对象、字体或逐页版式；复杂稿件须打开成品逐页检查。
- 写入公式不等于已经完成正确重算。不承诺全部 Excel 函数、外部链接、宏或复杂依赖的计算兼容性，关键结果必须重新计算并用已知样本校验。
- 已进行的 WPS 小样本打开与页面检查，只是对应样本的 QA 证据，不代表所有 Office 文件、复杂版式或全部公式都已验证。
- 生图、精修和试衣结果需要检查文字、人物一致性、商品细节与透明边缘；试衣仅作视觉示意，不保证实际尺码、材质或穿着效果。
- 内置图片与文档草稿明确标为示例。真实产物在独立区域显示；本地草稿调整不会自动无损修改原始真实文件。

## 本机数据与升级

- “我的项目”提供“使用中／回收站”。回收项目会从工作台和新任务选择中隐藏，费用继续归属原工作区；恢复后沿用同一个项目 ID、内容和费用。运行中、暂停或待人工确认的任务需先处理完成才能回收项目。
- 真实产物的删除操作会把文件移到本应用受管理的回收目录，产物区域可按项目查看并恢复；回收后不能预览、打开、另存或用于新任务。回收项目和回收文件分别操作，不自动批量移动所有关联文件。已另存到外部目录的副本不会随应用内回收而删除。
- 回收站不提供永久删除或自动清理，恢复不重新请求模型。文件被其他软件占用或本机写入失败时，应用会保留文件和恢复记录；请关闭占用程序后重新读取回收站核对状态，不要手工清理受管理目录。
- 工作区、项目、非秘密偏好和自定义提示词继续读取 `xuzuo-ui-prototype-v2`，不清空原有项目和演示账本。
- 分类、工作流、工作台功能及非秘密连接／模型配置使用独立的 `xuzuo-configuration-v1`；模拟运行记录使用 `xuzuo-workflow-runs-v1`。真实运行记录、真实账本、系统加密凭证及受管理产物保存在桌面应用数据目录。
- 分类、流程、提示词和工作台功能按工作区隔离；模型中心在本机共享。移动项目时保留内容与费用，并清除不属于目标区的分类引用；不会把原区整套模板、素材或流程一并复制。
- 文档本地草稿按项目 ID 保存。素材库的演示上传与收藏仍为按区会话缓存，刷新或重启后清空；通过真实流程桌面选择器导入的文件则进入受管理文件库，确认运行后才作为任务附件发送。
- 旧版本目录和数据保留，不通过清空存储或删除旧包完成升级。不要用旧窗口或旧安装包的结果代替新版验收。
- 浏览器预览、正式 EXE 和专用自测配置目录的数据彼此独立，不会自动跨环境导入或同步密钥。

### GitHub 自动更新

1.0.0 起，正式安装版从 [GitHub Releases](https://github.com/xiandan001/xuzuo-studio/releases) 获取更新。启动后约 3 秒检查一次，此后每 2 小时检查；休眠恢复后若已到检查时间则补查。更新按版本号比较，只接受更高正式版本，不安装草稿、预发布或旧版本。

设置 → 数据与版本中的“自动更新”为应用级开关，默认开启，修改立即保存。开启时发现新版会自动下载完整安装包并校验大小与 SHA-512；此版不使用增量下载。下载完成后继续正常使用，待用户正常退出、完成文件保存和任务收尾后，独立更新进程才会在原目录安装，不自动重新打开应用。取消勾选会停止自动检查和下载，也禁止已下载版本在退出时安装。退出取消、强制结束、关机或注销时延后更新。

更新沿用自定义安装器的文件校验、事务备份和失败回滚，保留工作区、作品、费用和本地密钥。开发模式、浏览器预览和未登记安装的目录运行版不自动覆盖安装；网络失败、限流或更新文件校验失败会在设置中显示结果，不打断创作。

旧版 0.17.1 没有更新客户端，第一次升级到 1.0.0 需下载并运行完整安装包；此后发布更高版本才会触发自动更新。发布时需创建与应用版本一致的正式 tag（例如 `v1.0.0`），将同一次构建的安装包、blockmap、manifest.json 和 latest.yml 上传到同一个 Release，资源齐全后再公开。普通代码推送不会发布更新，发布凭据不放入应用或仓库。

当前验证包含假 Key、fake fetch 的协议与异常测试，以及假 Key／本机 HTTP 服务的桌面完整链路检查。这些可验证请求结构、密钥隔离、文件生成、费用状态和恢复行为，**不等于用户账户或外网供应商已经成功调用**。此前已取得 OpenAI 文字接口的一次真实返回，完整成品链路及其它供应商和模态仍需分别验收，不能标记“所有主流模型全部已联网验收”。实际账户权限、网络可达性、额度、各型号效果与真实账单仍需由用户在 EXE 中逐项核对。
